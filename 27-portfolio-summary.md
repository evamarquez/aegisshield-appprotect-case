# Document 27 - Portfolio Summary

**Project:** AegisShield AppProtect  
**Case type:** Fictional product discovery and controlled pilot planning

## The problem

AegisShield wanted to evaluate a new product that could protect customer web applications without making legitimate bookings fail. The case focused on BookEasy, an existing SIEM customer with an online scheduling application.

## My role in the case

As Project Manager, I turned the sponsor request into a clear stage, coordinated Product, Engineering, Security, Design, Operations, QA, Customer Success, and BookEasy, and kept the work connected through scope, backlog, risks, decisions, tests, and handover.

## Main decisions

- Keep the first version limited to one BookEasy web application.
- Evaluate an established security engine instead of assuming a proprietary engine.
- Start in monitor mode before testing blocks.
- Require safe exception handling, audit records, access control, and recovery evidence.
- Approve a controlled pilot build but not production rollout.

## What happened in execution

A simulated rule blocked a legitimate booking in the test environment. The team moved the rule to monitor mode, narrowed the rule, created a time-limited exception, retested the flow, and closed the issue without changing the eight-week plan.

## Outcome

The fictional case ended with a sponsor-approved controlled pilot build, BookEasy acceptance of the agreed scenarios, a clear set of known limitations, and an operations handover. It does not claim a real customer launch, working security protection, or real research results.

## Evidence included

- Product discovery and sponsor decision.
- Project brief, charter, requirements, and stakeholder plan.
- Prototype and administrator journey.
- Technical approach, WBS, RACI, backlog, budget, capacity, and schedule.
- Test plan, risk register, data controls, issue log, and decision record.
- Pilot acceptance, release decision, handover, closure, and lessons learned.

## Key terms

**Portfolio case:** A structured example used to show how work is planned and managed.

**Simulated outcome:** A fictional result created for learning and demonstration.

**Evidence:** A document, test result, decision, or visual record that supports a project claim.
